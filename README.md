## Практическая работа № 14. Итоговый релиз

**Тема:** подготовка воспроизводимого запуска API, диагностика, контейнеризация и контроль качества.

**Автор:** Георгий  
**Группа:** ЭФБО-17-25  
**Вариант:** 8 — ограничение размера JSON-тела запроса.

### Назначение проекта

Проект предоставляет HTTP API для управления задачами и категориями. Клиент получает и изменяет данные через Express, а постоянное хранение выполняется в PostgreSQL. В составе релизной версии настроены health endpoints, структурированные логи, request ID, корректное завершение процесса, Docker Compose и GitHub Actions.

### Основные возможности

- получение списка категорий и задач;
- фильтрация задач по статусу, приоритету, категории и части названия;
- получение отдельной задачи по ID;
- создание, редактирование и удаление задач;
- проверка входных данных и единый формат ошибок;
- ограничение размера JSON-тела через `JSON_BODY_LIMIT_BYTES`;
- liveness и readiness endpoints;
- JSON-логи запросов с идентификатором запроса;
- завершение API по SIGINT/SIGTERM с закрытием HTTP-сервера и пула PostgreSQL.

### Требования к окружению

- Node.js 24.x;
- npm, входящий в комплект Node.js;
- PostgreSQL 18.x либо Docker Engine с Docker Compose v2;
- Git.

Фактические версии Node.js, npm, PostgreSQL и Docker нужно записать после запуска на компьютере, на котором выполняется работа. Требуемые версии не следует указывать как фактически установленные без проверки.

### Локальный запуск

1. Создать отдельную пустую учебную базу PostgreSQL и пользователя приложения.
2. Скопировать `.env.example` в `.env` и задать локальные параметры подключения. Пароли и файл `.env` нельзя добавлять в Git.
3. Установить зависимости и создать схему с исходными данными:

```bash
npm ci
npm run db:prepare
```

4. Запустить API:

```bash
npm start
```

5. В другом окне терминала выполнить smoke-проверку:

```bash
npm run smoke
```

Команда `npm run db:prepare` предназначена для новой пустой учебной базы: SQL-файл создаёт таблицы и добавляет стартовые данные. Не запускать её поверх существующей базы с пользовательскими данными.

### Проверки

```bash
npm test
npm run quality
npm run db:prepare
npm run test:db
npm run smoke
npm run release:files
```

- `npm test` запускает модульные и HTTP-интеграционные тесты без реальной базы.
- `npm run quality` проверяет форматирование, ESLint, отсутствие отключённых тестов, покрытие и релизные документы.
- `npm run test:db` запускает проверки на реальной PostgreSQL. Использовать только отдельную учебную базу.
- `npm run smoke` проверяет уже запущенный API и контрольный фильтр варианта 8.
- `npm run release:check` объединяет quality gate, подготовку новой пустой тестовой базы и DB-тесты. Для CI smoke выполняется отдельным шагом после старта сервера.

Фактическое количество тестов, результаты команд и версии инструментов необходимо перенести в отчёт после локального запуска. GitHub Actions показывает результат отдельного удалённого запуска; он не заменяет проверку на компьютере студента.

### Индивидуальный вариант 8

Для демонстрации размера тела используется переменная `JSON_BODY_LIMIT_BYTES`. Значение по умолчанию — 16384 байта; разрешённый диапазон — от 1024 до 1048576 байт.

При превышении лимита сервер возвращает HTTP 413 и код ошибки `PAYLOAD_TOO_LARGE`. Проверка находится в `tests/integration/release-variant-8.test.js`: она запускает HTTP-сервер с лимитом 1024 байта, отправляет более крупный JSON и проверяет статус и код ошибки. Значение лимита проверяется при чтении конфигурации и при создании JSON middleware.

### Health endpoints и логи

- `GET /health/live` отвечает, что процесс запущен, и не обращается к PostgreSQL.
- `GET /health/ready` проверяет соединение с PostgreSQL; при недоступной базе возвращает HTTP 503.
- `GET /api/health` сохраняет API health-контракт предыдущих работ.
- Каждый HTTP-запрос получает `X-Request-Id`; журнал содержит время, метод, путь, статус и длительность.
- Секретные значения в логах маскируются. Полная строка подключения и пароли не должны попадать в отчёт или скриншоты.

### Запуск через Docker Compose

Скопировать `.env.example` в `.env`, задать непустой `POSTGRES_PASSWORD` и выполнить:

```bash
docker compose up --build -d
docker compose ps
npm run smoke
docker compose down
```

Для просмотра журналов: `docker compose logs -f api db`. Данные PostgreSQL хранятся в именованном томе `postgres_data`. Команда `docker compose down -v` удаляет этот том вместе с данными; использовать её только при намеренном сбросе учебной базы.

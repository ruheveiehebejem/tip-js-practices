## Цель и результат

Реализован собственный Express API для чтения задач и категорий. Хранилище находится в памяти процесса. Сервер возвращает единый JSON-формат, поддерживает фильтры, корректно проверяет идентификаторы, отвечает на HEAD и OPTIONS и сообщает об ошибках с согласованными HTTP-статусами.

Операции POST, PATCH и DELETE намеренно не реализованы в ПР9: для известных маршрутов они возвращают 405. Изменения данных входят в следующую практическую работу.

## Разбор параметров

### ID

`parsePositiveId(raw)` возвращает положительное безопасное целое число или null. Сначала проверяется полная строка регулярным выражением `/^[1-9]\d*$/`, затем результат преобразуется в Number и проверяется через Number.isSafeInteger.

Принимаются значения `"1"`, `"4"` и `"9007199254740991"`. Отклоняются пустая строка, ноль, отрицательные числа, ведущие нули, десятичные числа, экспоненциальная запись, пробелы, суффиксы и числа за пределами безопасного диапазона. Один parseInt был бы недостаточен, потому что мог бы принять строку `"4abc"` за число 4.

### Query-параметры

`parseFilters(searchParams)` возвращает объект с полями:
- completed: boolean или null;
- priority: одна из строк low/medium/high или null;
- categoryId: положительное безопасное целое или null;
- q: строка после trim, по умолчанию пустая.

Перед преобразованием проверяются все неизвестные имена и повторения параметров. Значения completed должны быть строго `true` или `false`; priority чувствителен к регистру; categoryId не принимает ведущие нули. Длина q ограничена 100 единицами `length` после trim. Для ошибок применяется ApiError со статусом 400 и кодом INVALID_QUERY.

## Фильтрация и поиск

Все фильтры объединяются условием И. Значение completed сравнивается как boolean, priority и categoryId — со значениями соответствующих полей. Поиск выполняется по title без учёта регистра через `toLocaleLowerCase("ru-RU")`. Результат сохраняет исходный порядок и не изменяет переданный массив.

`findTask` ищет по полю id, а не по индексу, и возвращает null, если запись отсутствует.

## HTTP-маршруты

| Метод и путь | Успех | Формат |
|---|---:|---|
| GET /api/health | 200 | `{ data: { status: "ok" } }` |
| GET /api/categories | 200 | `{ data, meta: { total } }` |
| GET /api/tasks | 200 | `{ data, meta: { total, filters } }` |
| GET /api/tasks/:id | 200 | `{ data: task }` |
| HEAD для GET-маршрутов | Как у GET | Заголовки без тела |
| OPTIONS | 204 | CORS-заголовки без тела |

Пустая выборка возвращает 200 и пустой массив. meta.total — количество задач в текущей выборке, а не количество во всём хранилище. При корректном, но отсутствующем categoryId=999 возвращается пустой список, а не 404.

Для четырёх известных путей другие методы возвращают 405 METHOD_NOT_ALLOWED и заголовок `Allow: GET, HEAD, OPTIONS`. Неизвестный путь возвращает 404 ROUTE_NOT_FOUND. Неверный ID — 400 INVALID_ID, корректный, но отсутствующий ID — 404 TASK_NOT_FOUND и `details: { id }`.

CORS и общие заголовки включены в инфраструктуру приложения: `Access-Control-Allow-Origin: *`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Для 204 и HEAD тело отсутствует.

## Индивидуальный вариант 8

Начальный запрос:

```text
GET /api/tasks?completed=false&priority=high&categoryId=2
```

Ожидаемые ID: `[4, 34]`; `meta.total = 2`. Одновременно применяются три фильтра: задача невыполнена, имеет высокий приоритет и относится к категории 2 («Проект»).

Негативный запрос варианта:

```text
GET /api/tasks?completed=false&priority=high&categoryId=2&sort=id
```

Ожидается 400 INVALID_QUERY, потому что параметр sort неизвестен.

Дополнительные запросы:
- `GET /api/tasks/4` — 200, возвращается задача с ID 4.
- `GET /api/tasks/2` — 404 TASK_NOT_FOUND, `details.id = 2`.
- `GET /api/tasks/4abc` — 400 INVALID_ID.

### Ручные HTTP-запросы

```bash
curl -i "http://127.0.0.1:5505/api/tasks?completed=false&priority=high&categoryId=2"
curl -i "http://127.0.0.1:5505/api/tasks/4"
curl -i "http://127.0.0.1:5505/api/tasks/2"
curl -i "http://127.0.0.1:5505/api/tasks/4abc"
curl -i "http://127.0.0.1:5505/api/tasks?q=a&q=b"
curl -i -X POST "http://127.0.0.1:5505/api/tasks"
curl -I "http://127.0.0.1:5505/api/tasks"
curl -i -X OPTIONS "http://127.0.0.1:5505/api/tasks"
```

В PowerShell использовать `curl.exe`. В URL с амперсандом обязательны кавычки. Параметр `-i` показывает статус, заголовки и тело; `-I` выполняет HEAD.

## Контрольные вопросы

1. **Что делает Express?** Сопоставляет HTTP-метод и путь с обработчиком, предоставляет запрос и помогает формировать ответ.
2. **Чем req.params отличается от req.query?** params получает сегмент пути, query — параметры после знака вопроса.
3. **Почему нельзя использовать parseInt для ID?** Он может принять только начало строки и проигнорировать неправильный хвост.
4. **Почему completed=false нельзя преобразовывать через Boolean?** Любая непустая строка, в том числе "false", превращается в true.
5. **Что означает meta.total?** Размер сформированной выборки после применения фильтров.
6. **Почему отсутствие совпадений — не 404?** Маршрут и запрос корректны; просто подходящих записей нет.
7. **Зачем разделять validation, service и routes?** Проверка ввода, предметная логика и HTTP-ответы решают разные задачи и легче тестируются отдельно.
8. **Почему порядок middleware важен?** Первый обработчик, который завершит запрос, не даст более позднему маршруту выполнить работу.
9. **Чем 400 отличается от 404?** 400 означает некорректный ввод, 404 — корректно сформированный запрос к отсутствующему ресурсу или маршруту.
10. **Для чего нужен Allow?** Он сообщает методы, поддерживаемые конкретным маршрутом.
11. **Что делает HEAD?** Возвращает заголовки GET-ответа без тела.
12. **Что делает OPTIONS?** Позволяет клиенту узнать доступные параметры взаимодействия; в этом приложении ответ используется для CORS.
13. **Почему OPTIONS обрабатывается до router?** Чтобы ответить и на предварительные запросы к известным и неизвестным путям.
14. **Что такое CORS?** Браузерное правило доступа к ответам другого origin, а не средство аутентификации.
15. **Почему тесты создают отдельное приложение?** Это изолирует состояние и позволяет каждому тесту использовать собственный свободный порт.

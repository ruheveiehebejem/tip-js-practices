## Эксперименты с формой и хранилищем

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | Браузер не должен разрешить отправить форму. | Форма не отправляется, браузер показывает сообщение об обязательном поле. | Атрибут `required` выполняет нативную проверку HTML до отправки формы. |
| 2. Название из пробелов | Предполагается, что HTML может пропустить такое значение. | Прикладная проверка отклоняет название из пробелов. | `required` проверяет наличие символов, а `trim()` удаляет пробелы перед проверкой длины. |
| 3. Типы значений `FormData` | Значения обычных полей будут получены в виде строк. | Значения формы получаются строками. Числовой идентификатор преобразуется через `Number()`. | `FormData` возвращает значения элементов формы, а преобразование типов выполняется отдельно. |
| 4. Строка в `localStorage` и JSON | Объект должен преобразоваться в строку при сохранении. | Данные сохраняются в виде JSON-строки и восстанавливаются через `JSON.parse()`. | `localStorage` хранит строки, поэтому используются `JSON.stringify()` и `JSON.parse()`. |
| 5. Повреждённый JSON | При неправильной строке разбор должен вызвать ошибку. | Ошибка перехватывается, приложение использует исходный набор задач и показывает предупреждение. | Разбор JSON выполняется внутри `try/catch`, поэтому ошибка не останавливает приложение. |

## Организация кода

В проекте используются отдельные модули, каждый из которых отвечает за свою часть приложения.

| Модуль | Ответственность |
|---|---|
| `task-service.js` | Добавление, изменение статуса, редактирование и удаление задач. |
| `form-validation.js` | Проверка данных формы, поиск ошибок и нормализация названия. |
| `task-storage.js` | Сохранение, загрузка, проверка и удаление данных из `localStorage`. |
| `task-view.js` | Создание карточек задач, отображение списка и сводной информации. |
| `main.js` | Связывает модули, обрабатывает события пользователя и управляет состоянием приложения. |

Функции хранения получают объект `storage` аргументом, чтобы их можно было проверять отдельно от настоящего браузерного хранилища. Это также позволяет обрабатывать ошибки доступа к данным.

Данные из JSON проверяются перед использованием, потому что успешный `JSON.parse()` ещё не означает, что внутри находится правильный список задач. Проверяются версия данных, структура массива, идентификаторы, названия, статусы и приоритеты.

## Общий сценарий

В приложении предусмотрена работа с общим набором задач. Для проверки используется исходный список с идентификаторами `[1, 4, 7, 10]`.

| Шаг | Действие | Видимые id | Всего | Выполнено | Осталось | Прогресс | Состояние storage |
|---:|---|---|---:|---:|---:|---:|---|
| 0 | Исходный запуск после сброса | `[1, 4, 7, 10]` | 4 | 2 | 2 | 50.0% | Исходный набор |
| 1 | Добавление `id = 20` | `[1, 4, 7, 10, 20]` | 5 | 2 | 3 | 40.0% | Сохранён |
| 2 | Отказ для повторного `id = 4` | `[1, 4, 7, 10, 20]` | 5 | 2 | 3 | 40.0% | Без изменений |
| 3 | Редактирование `id = 4` | `[1, 4, 7, 10, 20]` | 5 | 2 | 3 | 40.0% | Сохранён |
| 4 | Переключение `id = 7` | `[1, 4, 7, 10, 20]` | 5 | 3 | 2 | 60.0% | Сохранён |
| 5 | Удаление `id = 1` | `[4, 7, 10, 20]` | 4 | 2 | 2 | 50.0% | Сохранён |
| 6 | Перезагрузка страницы | `[4, 7, 10, 20]` | 4 | 2 | 2 | 50.0% | Восстановлен |
| 7 | Сброс данных | `[1, 4, 7, 10]` | 4 | 2 | 2 | 50.0% | Ключ удалён |

При попытке добавить повторный идентификатор список не изменяется. При редактировании задачи меняются только название и приоритет. После перезагрузки данные восстанавливаются из `localStorage`.

6. Открыть общий набор и убедиться, что его данные не изменились.
7. Вернуться к индивидуальному набору и выполнить сброс.

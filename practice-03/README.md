## Организация кода

В проекте используются отдельные JavaScript-модули.

| Модуль | Ответственность |
|---|---|
| `task-service.js` | Работа с задачами: поиск, добавление, изменение статуса, удаление и получение статистики. |
| `task-selectors.js` | Фильтрация полного списка задач по выбранному статусу. |
| `task-view.js` | Создание карточек, отображение списка, сводки и пустых состояний. |
| `main.js` | Обработка событий пользователя, хранение текущего состояния и взаимодействие между модулями. |

Полный список задач хранится в переменной `currentTasks`. Выбранный фильтр хранится в `currentFilter`.

Видимый список рассчитывается отдельно с помощью `getVisibleTasks`. Это позволяет переключать фильтры без удаления задач из исходного массива.

События обрабатываются в `main.js`. Для кнопок карточек используется делегирование событий: обработчик назначается на общий список, а конкретное действие определяется через `closest` и атрибут `data-action`.

Сводка рассчитывается на основе полного массива задач через функцию `getTaskStats`, а не по количеству отображаемых карточек.

## Отладка и клавиатура

Для отладки использовались инструменты разработчика браузера.

В `handleTaskListClick` проверялись:

- `event.target` — элемент, на котором произошло нажатие;
- `event.currentTarget` — общий список, на котором установлен обработчик;
- `dataset.taskId` — идентификатор задачи в виде строки;
- числовой `id` после преобразования;
- значение `data-action`;
- результат вызова функции сервиса.

Также проверялась работа `closest`, которая позволяет определить кнопку даже при нажатии на вложенный `span`.

Для проверки некорректных идентификаторов использовались значения `777` и `4abc`. В обоих случаях приложение не должно изменять список задач.

Клавиатурное управление проверялось с помощью Tab, Enter и Space. После изменения статуса и удаления задачи фокус возвращается на соответствующий элемент интерфейса либо на активный фильтр.

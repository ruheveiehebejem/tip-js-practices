## Результат и границы

Создан компонентный интерфейс со списком задач, формой создания/редактирования, фильтрами и статистикой. Данные хранятся только в состоянии React. API, localStorage и useEffect в обязательную часть ПР7 не входят. После перезагрузки страницы появляется начальный набор.

## Компоненты и состояние

| Компонент | Ответственность |
|---|---|
| `App` | Владелец общего состояния tasks, filters и editingId. Вычисляет выборку, статистику и редактируемую задачу. |
| `TaskStats` | Показывает всего задач, выполнено и в работе по всему набору. |
| `TaskFilters` | Управляемые поля поиска, статуса, приоритета и категории; передаёт новые фильтры в App. |
| `TaskForm` | Хранит черновик и ошибки полей, проверяет данные и вызывает onSave. |
| `TaskList` | Показывает число найденных задач или пустое состояние. |
| `TaskItem` | Отображает задачу и передаёт действия переключения, редактирования и удаления. |

`App` хранит исходное состояние. Дочерние компоненты получают данные через props и сообщают о действиях через функции обратного вызова. Компоненты не изменяют полученные props.

Для создания и изменения массивов используются map, filter и spread. Входные объекты не меняются. У карточки ключ — `task.id`, поскольку идентификаторы не равны индексам массива и не меняются при фильтрации.

Статистика и список видимых задач вычисляются из tasks и filters на каждом рендере. Они не хранятся как отдельное состояние, поэтому не могут устареть после изменения исходного массива.

## Форма и валидация

Форма управляемая: каждое значение хранится в состоянии TaskForm. При отправке вызывается preventDefault, проверяются все три поля, а в App передаётся нормализованный объект:

- название — строка после trim, от 1 до 100 символов;
- приоритет — low, medium или high;
- categoryId — числовой ID существующей категории.

Ошибки выводятся рядом с соответствующими полями, а введённые значения сохраняются. После успешного создания форма очищается. При редактировании сохраняется completed; отмена не меняет задачу.

Для сброса черновика при переходе между разными задачами используется стабильный ключ формы на основе editingId. При удалении редактируемой записи режим редактирования сбрасывается. Подтверждение удаления выполняется до обновления состояния, а не внутри функции setState.

## Фильтры и статистика

Фильтры применяются совместно по условию И. Поиск учитывает регистр и пробелы по краям. Значение `completed` в управляемом поле — строка: явные сравнения с `"true"` и `"false"` предотвращают ошибку `Boolean("false")`.

Статистика рассчитана по полному массиву, а число найденных записей — по отфильтрованной выборке. Поэтому создание задачи, которая не подходит под текущие фильтры, увеличивает общий счётчик, но не добавляет карточку в текущий список.

## Контрольные вопросы

1. **Чем JSX отличается от HTML?** JSX — синтаксис JavaScript для описания элементов интерфейса. Его обрабатывает сборщик, это не строка HTML.
2. **Props и state?** Props приходят от родителя, state хранится внутри компонента и меняется через setter.
3. **Почему обычная переменная не заменяет useState?** React не отслеживает её изменение и не перерисовывает компонент.
4. **Когда использовать функциональный setter?** Когда новое состояние зависит от предыдущего.
5. **Почему нельзя менять объект в копии массива?** Копия массива не копирует вложенные объекты, поэтому меняется и исходная запись.
6. **Зачем key?** Он помогает React связать элемент списка с конкретной записью; нужен стабильный ID.
7. **Почему выборка и статистика не отдельные state?** Это производные значения, их можно вычислить из основных данных.
8. **Как дочерний компонент сообщает о действии?** Вызывает callback, переданный родителем через props.
9. **Что делает поле управляемым?** Значение приходит из state, а onChange обновляет этот state.
10. **Почему categoryId преобразуется?** Значения select — строки, а в модели категория хранится числом.
11. **Как смена key влияет на форму?** React создаёт новый экземпляр компонента и его локальное состояние сбрасывается.
12. **Почему confirm не помещается в setter?** Функция обновления должна быть чистой; подтверждение — побочный эффект.
13. **Как отличить пустой список от пустой выборки?** Список задач остаётся, но ни одна запись не подходит активным фильтрам; интерфейс всё равно показывает empty state.
14. **Что проверяет npm test?** Чистые функции предметной логики, но не полный браузерный интерфейс.
15. **Что изменится при подключении API в ПР8?** Синхронные локальные операции заменятся асинхронными запросами, потребуется loading/error и повторная загрузка.
